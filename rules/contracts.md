# Contracts & generated code (MEDIUM)

For teams that define wire contracts (OpenAPI, protobuf, event schemas) as the source of truth and generate stubs, clients, and payload types from them. If you hand-write wire types instead, the existing `_dto` translators already cover you and this file does not apply.

```
api/          # SOURCES OF TRUTH — you edit these
    openapi/<domain>/            HTTP specs
    proto/<domain>/v1/           gRPC and event specs
gen/          # GENERATED — never edited, never hand-reviewed
    openapi/<domain>/            server stubs, clients, wire types
    proto/<domain>/v1/           gRPC stubs, event payload types
```

Specs are grouped by domain and versioned by folder (`v1`, `v2`). Generated output mirrors the same shape.

## contract-gen-edge-only

Generated code is **wire format**, so it follows the same rule as any translator type (`layer-dto-no-leak`): it lives at the edge and never crosses into the core.

| Generated code may be imported by | Never by |
|---|---|
| `transport/<protocol>/<domain>` and its `_dto` | `entities`, `errors`, `service`, ports |
| `<domain>/gateway/<impl>` and its `_dto` (generated clients) | other domains |
| `<domain>/publisher` adapter and `transport/consumer/<domain>_dto` (event payloads) | `platform` (except `platform/<protocol>` wire primitives) |

**Wrong**
```
# orders/service
import gen.openapi.orders.CreateOrderRequest      # wire type in the service signature
```

**Right**
```
# transport/rest/orders_dto
toEntity(req: gen.openapi.orders.CreateOrderRequest) -> orders.entities.NewOrder
```

Add `gen/` to the boundary lint with exactly the table above.

## contract-entities-not-generated

Entities are never generated from a wire spec. If `Order` is derived from the OpenAPI schema, every wire change edits the domain model and invariants have nowhere to live. Entities keep their own definition; the `_dto` translator maps between them and the generated wire types. A scaffold may emit an entity **skeleton** once (see `manifest-hand-owned-files`); after that the entity is hand-owned.

## contract-generated-is-read-only

- `gen/` is regenerated by one command (`make gen` or equivalent) and every file carries a "generated, do not edit" header.
- CI regenerates and fails if the working tree differs (**drift check**). Generated code is committed or reproducibly built, never half-and-half.
- Fix a generated file by changing the spec or the generator template, never the output.

## contract-remote-peer-is-gateway

When domain `orders` calls `payments` **in the same process**, `orders` depends on payments' `service` port (`structure-cross-domain-imports`). When `payments` runs as a **separate process**, that dependency becomes a network call and is modelled as a gateway:

```
orders/gateway                 PaymentGateway            # port declared by orders, in orders' terms
orders/gateway/paymentsrpc     adapter using gen/proto/payments/v1 client
orders/gateway/paymentsrpc_dto gen types <-> orders entities, remote failure -> orders domain errors
```

- The port is `orders`' own role-named port, not payments' service port and not the generated client.
- Timeouts, retries that respect the contract, and circuit breaking follow `crosscutting-decorators`; failures translate to domain errors (`errors-adapters-translate`).
- Moving a domain between "same process" and "own process" changes only the adapter wired in `app/`: the port, `service`, and tests stay as they are.

## contract-events

- Event schemas live in `api/proto/<domain>/v1` (or your schema registry's equivalent), owned by the publishing domain, named in past tense.
- The domain's published event **types** are its public API (`structure-public-api`). The generated payload type is the wire format of that event and stays at the edge: the `publisher` adapter translates event entity → payload on the way out, and `transport/consumer/<domain>_dto` translates payload → entity on the way in.
- Payload evolution follows `api-versioning`: additive changes in place, breaking changes in a new version folder.

## contract-breaking-change-check

CI runs a breaking-change detector against the default branch for every spec (for example `buf breaking` for protobuf, `oasdiff` for OpenAPI). A breaking change must be a new version folder with its own transport, per `solid` Open/Closed and `api-versioning`.
